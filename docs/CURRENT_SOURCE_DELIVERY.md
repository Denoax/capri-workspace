# Current source and preserved history

Source verification uses an explicit `source_delivery` pair in the frozen
current-context binding. Its manifest and ZIP live under `current-source/` and
are bound reference originals. The older `authority/SOURCE_MANIFEST.json` and
`authority/source.zip` remain unchanged historical evidence. Frozen legacy
packets keep their original guide; a new condition must select its current pair.

The shared pure verifier checks the expected inventory identity, exact ZIP
members, bytes and regular-file modes. The directed role command imports that
verifier from the read-only controller mount. Parent admission also executes it
before launching a model. The source bundle is built outside the source tree,
avoiding an archive/source hash cycle. Bulk evidence is bounded at32MB total,
32MB per file and64MB uncompressed ZIP content; these are evidence limits. The
60,000-byte frozen contract, role/stage240s/12tools and60s compaction caps do not
change. Binary archives are not inlined into model context sections.

An explicit owner-material revision supports the observed completed read-only
source hold before any task submission. It requires the prior consumed launch
and foreground scope, exact held state, matching successful terminals for all
three Thinker turns, no Doer/Reviewer turn, no tasks/attempts/human effects,
revoked owner capability, unchanged source/input snapshots, dead owned processes
and absent endpoints. Unknown or uncertain effects cannot use this route.

A new source/material condition uses the existing Store locks/events and real
controlling-terminal boundary. Preparation grants no dispatch by itself. Launch
revalidates and commits one non-replayable intent before creating its fresh
ordinary Engine home. Prior cases, scopes, typed holds, counters and files remain
preserved. Generic resume and all protected core semantics remain unchanged.
No unit check establishes completed qualification, billing savings or approval.

The old source069 UI socket retains its original inode/UID but has a different
ctime after the recorded outer-view attach/close window. Its exact cause is not
asserted. A separately bound audit preserves this unregistered inactive artifact
without cleanup or resume, verifies all prior processes and view process exited,
and leaves old ownership records unchanged. Role/model endpoints must be absent.
Future terminal shutdown records the latest same-inode state after verified
owned session closure and listener exit, retaining the creation identity too.
The generic stale-socket ownership check remains strict.
