# V2 authority boundary

Trust the uncompromised owner session, kernel/compositor, fixed native coordinator/bootstrap, installed applications and authenticated provider transport. Same-UID/root compromise and physical use of an unlocked session remain outside this boundary. An executable/UID check does not cryptographically authenticate a human.

Only the exact native Quickshell configuration, checked with SO_PEERCRED and a per-launch token, can submit monotonically sequenced owner events. Observers cannot submit tasks or expansion decisions. Provider/model/file/mail/memory objects never become owner input. Displayed text is plain text. Credentials and control sockets are private and absent from worker mounts and model context.

Chat preserves the direct conversation path. Commands retain exact V1 single-action grants. Task mode mints a native lease binding owner event, account/model, graphical session, broker epoch, policy, held directory identities, deadline and budgets. Validity is checked outside the model before each tool. Action IDs are consumed and durably journaled before effects; uncertain outcomes are reconciled, never replayed automatically. Stop, lock/suspend, UI loss, expiry and account/model changes revoke work.

The pinned Codex sidecar runs with a private profile at the unchanged HOME/CODEX_HOME locations inside its mount namespace. Its read-only project mounts, stdio control plane and task-bound authenticated loopback relay are separate from untrusted command workers. The relay allows only the selected plan model and registered Capri functions; other advertised harness families are removed and unknown output tools rejected before dispatch. It cannot mint native authority. No other Codex credentials or global settings are read/changed, and no alternate paid provider is used.

Command workers use held project directory FDs, isolated PID/mount/network namespaces, a clean environment, no desktop sockets/home/protected credential mounts, closed inherited FDs, bounded output and registered systemd scopes. The trusted gate establishes resource controls before executing the program and binds child lifetime to an exact owner pidfd. Writable mounts cannot escape to host paths through symlinks or a swapped directory name. Selected roots may still contain sensitive data: choosing a project does not sanitize its contents. General network, root privileges, arbitrary GUI input and live Capri/bootstrap/venv/state writes remain unavailable.

Background observation has no shell/lease. Selected-project subscriptions read save-event counts, not arbitrary filenames, titles, buffers or code. Supported Wayland input-idle signals contain no keys. Persistent scheduler eligibility handles deduplication, budgets, debounce, cooldowns and conservative clock jumps. Missing idle/DND evidence suppresses unsolicited speech. Explicit data-sharing selection is separate from permission to execute.

Gmail uses a separate registered desktop OAuth client with PKCE/state and a loopback callback. Only fixed Google token/profile/message endpoints are used; reads are GET-only, redirects rejected, labels/page size bounded, and send/modify unavailable. Raw bodies are ephemeral; HTML, remote images and attachments are never fetched/executed as active content. Account switches discard old in-flight results. Mail text cannot approve actions or changes to permissions.

Self-authored source is staged outside live versions and verified inside a credential-free sandbox. Native review binds a passing receipt and exact content digest. Changed bytes invalidate installation. The protected bootstrap owns version metadata/current pointer, last-known-good and one crash rollback. Candidate code cannot rewrite its running authority or establish its own release signing trust. There is no configured automatic trusted release channel. Uninstall verifies registered file hashes and preserves changed user files/private state.

ScreenCast does not establish RemoteDesktop input. No permanent root model/input service, public control server, borrowed cookies, arbitrary hook loader, microphone or clipboard watcher is installed. Development pointer/keyboard fixtures stay outside the product and prove only the guarded native acceptance flow. Physical-device, continuous-motion and full-session lifecycle claims require actual host evidence.
