# Native intake refinement — experimental, qualification pending

Three native Sol roles, medium/medium/high efforts, 240 seconds/12 tools per turn
and combined stage, and 60-second compaction are unchanged. Protected core,
Engine behavior and human gates are unchanged. Offline checks do not establish a
complete native cycle.

The parent prepares source-bound `current-context/INDEX.json` and ordered named
sections. Complete N01–N08 values, current scope, exact answers/corrections and the
task view remain readable. Referenced duplicate requirements must equal the
original values. Every original has an explicit classification, hash and retained
access path. Parent-reviewed coverage links are not automated semantic proof;
summaries are navigation, never replacement authority.

Initial intake and owner recovery share this read contract. Sections have explicit
cursors and at most 16,384 output bytes. Planning counts reads, checks, hosted
research, ordinary full submission and two contingency calls inside the existing
stage. It measures the complete serialized frozen contract after lineage,
answers and reserved research fields. Time estimates do not establish latency.
Probes, recovery and work retain the actual shared deadline and counters.

Requested output limits may be capped. The native grader requires ordered paired
command events, exact complete output and those same bytes in public function
outputs of the exact thread/turn. Missing/truncated delivery holds before MCP
submission. Private reasoning is excluded. Integrity and delivery do not prove
comprehension; behavior still needs the task, checks and qualification evidence.
No speculative template-reference submission interface was added.

Each generation owns bounded fsynced `received-frames.jsonl`. Receipt-only public
metadata precedes decode/lifecycle validation; validation/rejection links to the
receive sequence. Raw commands/results/reasoning and arbitrary strings are
excluded or hashed. Sink failure/overflow holds work. State-changing observers
remain after validation and failures latch. The sole reader uses no SQLite or
recursive callbacks; receipt I/O precedes backend validation. A partial record or
missing result remains a gap. `item/started` is an observation, not an atomic
pre-execution gate: the stronger never-start-a-thirteenth-tool claim is unverified.
Filesystem, capability and writer boundaries remain the effect controls.

The native CLI adds `fence-owner-intake --binding FENCE.json --check`. It checks
existing state read-only. Without `--check`, genuine foreground confirmation is
required. It records one append-only Store event; exact duplicate/lost-response
requests return that result and can reconstruct a missing receipt projection.
Lock order is native-startup, native-writer, Store transaction. Changed parameters,
live/reused PIDs, active/unowned endpoints, source/registry/input/capture drift,
extra tasks/turns, capabilities and pending questions hold.

This fence profile covers only the reviewed stopped stabilization intake, correct
scope 198 and consumed claim 194. The exact known captures establish its observed
read-only effects; the lost thirteenth start remains a gap, never a manufactured
completion. An exact owned non-listening socket of the recorded exited server can
remain preserved. Unknown/write attempts cannot use this profile. Fencing grants
no dispatch or acceptance authority.

`prepare-maintenance` is separate new source-bound foreground admission and
revalidates the fence. It preserves the prior abort/ledger/counters and declares a
new source/evaluation condition. `recover-startup` consumes its own launch once,
qualifies context delivery with submission held, then permits scoped work.
Completed question/source/budget holds remain distinct from interrupted effects.
Questions require the existing durable core question and bound human answer;
answers must appear in a rebuilt packet before checked new admission. No hold
silently retries. Sealed-task restart and formal-review operations stay distinct.

CI diagnostics now read kernel/AppArmor evidence after the collector probe.
`--ci-kernel-logs` only reads privileged diagnostics on an ephemeral runner; it
changes no sysctl, profile or collector flag. A failed probe means prerequisite
failure and suite NOT_RUN. A supported environment needs both a passing actual
probe and complete nonzero suite.

The verified private repository was renamed to `Denoax/capri`, the same repository
identity. Runtime branches and separate CAPRI presentation remain distinct. Export
only curated code, never input packs, raw reviews, state/auth, notes or private
fork history. Keep original/v2 rows and use a separate frozen runset for new code.
Actual visible clients, native cycle, lifecycle recovery and sole formal review
remain qualification obligations. Incomplete work stays BLOCKED; a completed
formal report ends at AWAITING_HUMAN. No acceptance, integration or release follows.
