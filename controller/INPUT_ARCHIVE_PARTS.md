# Native source evidence and the unchanged input inventory

Every mounted input remains at most 8,000,000 bytes. An exact source ZIP may be
delivered as an ordered list of parts under `current-source/`; their concatenated
bytes must pass the existing complete manifest/content/mode verifier. Total bulk
evidence remains at most 32,000,000 bytes. The generated role command and parent
admission use the same verifier. No source, role, checkpoint, context, tool, time
or compaction limit increases. Generic `tree`, native adapter, operator and
checked-resume logic remain unchanged.

`load_materials` now rejects an oversized mounted file during pure admission,
before an intent, initializer, socket or role process. Legacy single-part source
bindings remain supported when they fit the same per-file limit.

The source-delivery attempt273 is preserved as failed/uncertain, not rewritten.
The added variant of the existing startup-repair route admits only its exact
pre-dispatch inventory failure: known milestones/error, no owner dispatch or
task/attempt/human effects, empty read-only roles, revoked capability, exact
stopped source/config/materials/processes/terminal identities, and public receive
evidence with no model lifecycle or turn identity. Distinct foreground input and
new source are required; the original intent can never be replayed. Any model
effect or drift fails closed. The prior large source archive remains bound in
the old immutable condition and explicitly linked by INPUT_REPAIR_LINEAGE.json;
its historical scope/answers are preserved, and current source gets new parts.

Offline tests are technical evidence only. Native qualification, benchmarks and
the sole formal Reviewer/report still require actual admitted execution.
